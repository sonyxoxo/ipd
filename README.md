# Изменение суточного профиля электропотребления домохозяйства

Научно-исследовательский проект по анализу реальных поминутных измерений электропотребления одного домохозяйства.

**Тема исследования:** «Изменение суточного профиля электропотребления домохозяйства: влияние полноты исходных данных и методов их обработки на результаты анализа».

## 1. Цель исследования

Цель работы — исследовать изменение суточного профиля активной электрической мощности домохозяйства и оценить влияние полноты экспериментальных данных, выбора временного интервала и методов математической обработки на полученные результаты.

Исследование проводится по двум основным направлениям:

1. Сравнение суточных профилей электропотребления в разные сезоны.
2. Изучение влияния отсутствующих измерений и методов обработки на характеристики суточного профиля.

Основной анализируемой физической величиной является активная электрическая мощность, выраженная в киловаттах (кВт).

## 2. Исходные данные

Используется открытый набор данных [Individual Household Electric Power Consumption](https://archive.ics.uci.edu/dataset/235/individual+household+electric+power+consumption) из UCI Machine Learning Repository.

Авторы: Georges Hebrail, Alice Berard.

DOI: https://doi.org/10.24432/C58K54

Набор содержит поминутные измерения электрических величин одного домохозяйства за период с декабря 2006 года по ноябрь 2010 года.

Основные характеристики используемого файла:

| Характеристика | Значение |
|---|---|
| Файл в репозитории | `data/raw/household_power_consumption.zip` (внутри исходный TXT) |
| Количество записей | 2 075 259 |
| Количество исходных столбцов | 9 |
| Начало наблюдений | 16.12.2006, 17:24 |
| Конец наблюдений | 26.11.2010, 21:02 |
| Интервал регистрации | 1 минута |
| Разделитель | `;` |
| Размер файла | 132 960 755 байт |

Основная переменная — `Global_active_power`, содержащая среднюю за минуту активную мощность домохозяйства в кВт.

Дополнительно представлены реактивная мощность, напряжение, сила тока и показания трёх дополнительных счётчиков электрической энергии.

При предварительном аудите обнаружено 25 979 записей с отсутствующими измерениями. При этом временные метки образуют непрерывную поминутную последовательность.

Исходный файл сохраняется без изменений. Все преобразования выполняются в отдельных рабочих таблицах.

## 4. Программные средства

Основная обработка данных выполняется на языке Python в Jupyter Notebook,
Google Colab или из командной строки. Во всех вариантах источником является
файл **в репозитории**: ручная загрузка в текущий сеанс Colab не используется.

Общие функции содержатся в `ipd_analysis.py`; каждый ноутбук читает выбранный
файл один раз и выполняет только свою часть исследования. Для пакетного
анализа используется `run_analysis.py`.

Используемые библиотеки:

- **pandas** — работа с таблицами и временными рядами;
- **NumPy** — численные вычисления;
- **Matplotlib** — построение научных графиков.

Для реализованных расчётов SciPy и SymPy не требуются. Список зависимостей
приведён в `requirements.txt`.

Работоспособность проверена на Python 3.12, pandas 2.2.3, NumPy 2.3.5
и Matplotlib 3.10.8. В каждом наборе результатов файл `metadata.json`
содержит фактически использованные версии и контрольные суммы исходника и кода.

Для дополнительной визуализации используется LabPlot 2.12.

GitHub применяется для публикации программного кода, графиков, результатов и научной документации.

эксперименте. Дополнительно исследуется устойчивость результатов: 100
случайных выборок пропусков и все возможные положения непрерывного блока
с началом в 00:00. Квантили характеризуют разброс изученных сценариев,
а не доверительный интервал для всех домохозяйств.

[График разброса ошибок](<графики/05_устойчивость_к_пропускам.png>) и
[таблица сценариев](<статистические результаты/05_устойчивость_сценарии.csv>)
позволяют проверить влияние конкретного расположения пропусков.

Для сентября 2008 года ошибка MAE исходного опыта с непрерывным пропуском
15–17 сентября равна **0,029354 кВт**. Но средняя MAE по 28 возможным
положениям такого блока составляет **0,035163 кВт**; для 100 случайных
вариантов — **0,033839 кВт**. Это показывает, почему нельзя делать общий
вывод о преимуществе одного типа пропусков по единственному примеру.

## 6. Основные результаты

Получены следующие среднемесячные значения активной мощности:

| Месяц | Средняя мощность, кВт | Полнота данных, % |
|---|---:|---:|
| Январь 2008 | 1,460 | 99,998 |
| Апрель 2008 | 1,116 | 100,000 |
| Июль 2008 | 0,795 | 99,996 |
| Сентябрь 2008 | 0,988 | 100,000 |
| Август 2009 | 0,665 | 98,004 |
| Август 2010 | 0,591 | 83,813 |

В выбранных месяцах 2008 года наблюдаются различия среднего уровня активной мощности и формы суточных профилей.

Максимумы средних почасовых профилей четырёх сезонных месяцев приходятся на вечернее время.

Сравнение среднего арифметического и медианы показало зависимость характеристик суточного профиля от метода усреднения.

Увеличение окна скользящего среднего приводит к уменьшению выраженности локальных максимумов.

Эксперименты с пропусками показали, что результаты зависят не только от доли отсутствующих измерений, но и от их расположения во времени.

Полученные различия характеризуют исследуемое домохозяйство. Причины сезонных изменений требуют дополнительных данных и не рассматриваются как доказанные.

## 7. Воспроизведение результатов

Для повторного выполнения расчётов необходимо:

1. Клонировать репозиторий: `git clone https://github.com/sonyxoxo/ipd.git`.
2. Перейти в его каталог: `cd ipd`.
3. При необходимости установить зависимости: `pip install -r requirements.txt`.
4. Убедиться, что исходный ZIP находится в `data/raw`; другие файлы того же
   формата также добавлять в этот каталог и фиксировать в Git.
5. Запустить все файлы: `python run_analysis.py --all`.
6. Открыть CSV и рисунки в `результаты/<имя-источника>-<код>/`.
   Сведения об источнике, коде и версиях программ находятся в `metadata.json`.
7. Для учебного пошагового разбора запускать пять ноутбуков из
   `ноутбуки python`. В Colab первый блок клонирует репозиторий в `/content/ipd`
   **только если клона ещё нет**. При обновлении GitHub выполняйте
   `git -C /content/ipd pull --ff-only` вручную.

После публикации новой версии в GitHub может запускаться проверка
`.github/workflows/tests.yml` (если GitHub Actions разрешены в репозитории):
все автоматические тесты и полный расчёт
по отслеживаемому ZIP. Успешный локальный запуск не заменяет проверку
на чистом клоне, поэтому статус этой проверки нужно смотреть во вкладке
**Actions** на сайте GitHub.

Google Colab очищает временную файловую систему при завершении сессии, поэтому
новую сессию начинают с повторного клонирования **репозитория**, а не с
ручного повторного выбора файлов. Сами файлы и код остаются в GitHub.

Если в `data/raw` больше одного файла, в ноутбуке нужно явно указать
`source = choose_source("data/raw/имя.csv")`. Для обработки всех файлов без
ручного выбора используйте `--all`.

### Новые измерители: названия столбцов и единицы

Для файла, например, `data/raw/meter_example.csv` с заголовками
`datetime;power_w`, добавьте сопоставление в **`analysis_config.json`**:

```json
{
  "datasets": {
    "meter_example.csv": {
      "columns": {"timestamp": "datetime", "Global_active_power": "power_w"},
      "units": {"Global_active_power": "W"},
      "sampling_minutes": 1,
      "delimiter": ";"
    }
  }
}
```

Программа преобразует ватты в киловатты **до** расчётов и сохранит выбор
в метаданных запуска. Формат даты при необходимости задаётся в
`date_format` (синтаксис Python `strptime`). Для нескольких файлов создайте
отдельный объект внутри `datasets` для каждого имени.

Поддерживаются измерения **с шагом в одну минуту**. Источники с шагом
5 или 15 минут требуют иной временной сетки и формулы энергии; программа
выдаёт явную ошибку, а не притворяется, что данные поминутные.
Неизвестные единицы также отвергаются, чтобы не получать неверные результаты.

Заголовки опубликованных CSV приведены к латинским именам без изменения
численных данных. Скрипт `scripts/standardize_legacy_tables.py` позволяет
повторить преобразование. Смысл переменных объяснён в ноутбуках и
[инструкции](ИНСТРУКЦИЯ_ПО_ИСПРАВЛЕНИЯМ.md).

Подробная инструкция: [Исправления и запуск](ИНСТРУКЦИЯ_ПО_ИСПРАВЛЕНИЯМ.md).

Для проверки корректности загрузки используются следующие характеристики:

- 2 075 259 записей;
- 9 исходных столбцов;
- 25 979 записей с отсутствующей активной мощностью;
- отсутствие пропущенных временных меток в проверенном диапазоне.

## 8. Ограничения исследования

Исследование основано на наблюдениях одного домохозяйства.

Сравнение отдельных месяцев разных сезонов не позволяет автоматически распространять результаты на другие годы и другие дома.

Влияние отсутствующих измерений зависит от продолжительности и расположения пропусков.

Математическое сглаживание может изменять величину локальных максимумов и форму суточного профиля.

Полученные результаты интерпретируются с учётом использованных методов и ограничений исходного набора данных.

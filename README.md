# Изменение суточного профиля электропотребления домохозяйства

Исследование суточного профиля активной электрической мощности на основе поминутных измерений одного домохозяйства.

**Тема исследования:** «Изменение суточного профиля электропотребления домохозяйства: влияние полноты исходных данных и методов их обработки на результаты анализа».

## 1. Цель исследования

Исследовать различия суточных профилей электрической мощности в выбранные периоды, влияние отсутствующих измерений и способов обработки на получаемые статистические характеристики.

Основная анализируемая величина — `Global_active_power`, средняя за минуту активная электрическая мощность, кВт.

## 2. Исходные данные

Используется набор [Individual Household Electric Power Consumption](https://archive.ics.uci.edu/dataset/235/individual+household+electric+power+consumption), предоставленный UCI Machine Learning Repository (Georges Hebrail, Alice Berard).

| Характеристика | Значение |
|---|---|
| Исходный файл | [household_power_consumption.zip](data/raw/household_power_consumption.zip) |
| Период | 16.12.2006 17:24 — 26.11.2010 21:02 |
| Количество записей | 2 075 259 |
| Интервал измерений | 1 минута |
| Столбцов в исходном файле | 9 |
| Отсутствует активная мощность | В 25 979 строках |
| Пропущенных временных меток | 0 |

Исходный ZIP не изменяется. Пропущенные значения мощности не считаются нулевым потреблением. Показания трёх дополнительных счётчиков содержат энергию в Вт·ч за минуту и не подменяют активную мощность.

## 4. Программные средства

Основные вычисления выполняются на Python с библиотеками **pandas**, **NumPy** и **Matplotlib**. Используются Google Colab и Jupyter Notebook. Для дополнительной визуализации предусмотрен LabPlot 2.12.

Функции загрузки, проверки временной сетки и статистической обработки вынесены в `ipd_analysis.py`. Модуль `run_analysis.py` выполняет пакетную обработку исходных файлов.

Поддерживаются поминутные TXT, CSV, TSV и ZIP со значениями времени и активной мощности. Для нестандартных названий столбцов и физических единиц предусмотрен `analysis_config.json`. Для данных иной периодичности необходима адаптация методики.

### Проверка научных гипотез

На шестом этапе проверены три гипотезы: различие суточных профилей, влияние количества и расположения пропусков, влияние метода обработки неполных измерений.

**H1.** Различия формы и размаха почасовых профилей января, апреля, июля и сентября 2008 года статистически значимы при выбранной процедуре проверки (`p` после поправки Холма: 0,003–0,004). Для времени максимума значимого различия не установлено. Разность средних мощностей января и июля по пятидневным блокам составляет 0,6414 кВт (95%-й бутстреп-интервал: 0,5260–0,7688 кВт).

**H2.** На сентябре 2008 года смоделированы пропуски 1%, 5%, 10% и 20% трёх типов. При 10% пропусков средняя MAE равна 0,03387 кВт для случайных, 0,03478 кВт для непрерывных и 0,02961 кВт для вечерних удалений.

**H3.** Для коротких случайных разрывов 10%-ная потеря измерений после линейной интерполяции дала MAE 0,00549 кВт против 0,03385 кВт без восстановления; длинные непрерывные разрывы интерполяцией коротких промежутков не исправляются.

Ноутбук: [Проверка научных гипотез](<ноутбуки python/06_проверка_научных_гипотез.ipynb>).

## 7. Воспроизведение результатов

Для обработки нужны Python и библиотеки из `requirements.txt`. Исходные файлы находятся в `data/raw`. После клонирования репозитория установка и запуск выполняются командами:

```bash
python -m pip install -r requirements.txt
python run_analysis.py --all
```

В Google Colab шестой ноутбук получает данные из копии репозитория `sonyxoxo/ipd` и сохраняет результаты в отдельный каталог каждого источника. Исходный ZIP при этом не меняется. Итоговые таблицы и графики опубликованы в репозитории отдельно от временных результатов.

## 8. Ограничения исследования

Исследованы измерения одного домохозяйства. Сравнение отдельных месяцев не позволяет делать вывод о закономерностях других лет и домохозяйств. Минутные наблюдения зависимы во времени. Эксперименты с искусственными пропусками позволяют оценить поведение алгоритмов при заданных схемах исключения данных, но не раскрывают причины реальных пропусков. Статистическая значимость не доказывает причинную связь. Сглаживание не является восстановлением отсутствующих измерений.

# Разбор ошибок и инструкция по работе с репозиторием

**Проект:** `sonyxoxo/ipd` — исследование поминутного электропотребления домохозяйства.

**Проверены все пять ноутбуков:** первичный аудит, проверка времени и
полноты, преобразование физических величин, визуализация,
статистическая обработка. Старые ноутбуки содержали повторяющийся код;
теперь их расчёты используют один модуль `ipd_analysis.py`.

## 2. Как теперь устроена работа

```text
GitHub: sonyxoxo/ipd
  data/raw/*.zip, *.txt, *.csv, *.tsv   ← исходники под управлением Git
       ↓
  ipd_analysis.load_measurements()     ← чтение в pandas один раз на файл
       ↓
  regular_minutes()                    ← временная сетка и NaN, без интерполяции
       ↓
  аудит → полнота → энергия → профили → статистика
       ↓
  результаты/<источник>-<код>/         ← CSV и графики отдельно по каждому файлу
```

`run_analysis.py --all` выполняет эту последовательность **поочерёдно для
каждого файла**. Разные домохозяйства и периоды не смешиваются. Для отдельного
этапа можно открыть соответствующий Jupyter-ноутбук; при этом один и тот же
общий модуль гарантирует одинаковые формулы.

### Что означает «один раз загрузить в pandas»

В **одном запуске** ноутбука выполняется один `load_measurements(source)`, и
далее функции работают с `measurements` или производной таблицей `minutes`.
Между **разными** сессиями Colab память Python не сохраняется: `pandas` не
может магически хранить DataFrame в GitHub. Поэтому новый сеанс заново
читает тот же проверенный файл из **клона репозитория**, без `files.upload()`.

## 3. Точные действия: GitHub → Python / Colab

### Вариант А. На компьютере

1. Откройте терминал, Git Bash или командную строку.
2. Скачайте репозиторий: `git clone https://github.com/sonyxoxo/ipd.git`.
3. Перейдите в него: `cd ipd`.
4. Установите библиотеки: `python -m pip install -r requirements.txt`.
5. Убедитесь, что в `data/raw/` есть `household_power_consumption.zip`.
6. Запустите `python run_analysis.py --all`.
7. Откройте появившуюся папку `результаты/household_power_consumption-.../`.
   Внутри — таблицы анализа и графики.
8. Для одного файла: `python run_analysis.py --file data/raw/household_power_consumption.zip`.

На Windows иногда нужно вызывать `py` вместо `python`. На некоторых
системах — `python3`.

### Вариант Б. В Google Colab

1. Откройте один из пяти ноутбуков через GitHub.
2. Запустите **первую кодовую ячейку**. Она найдёт клон `ipd` либо выполнит
   `git clone --depth 1 https://github.com/sonyxoxo/ipd.git /content/ipd`.
3. Эта ячейка читает один файл из `data/raw` в `measurements`. Не нажимайте
   «Загрузить файл»: такого действия больше нет.
4. Запустите последующие ячейки. Они используют уже подготовленные данные.
5. Если вы изменили файлы в GitHub, перед новым запуском ячеек выполните
   `!git -C /content/ipd pull --ff-only` (если в локальном клоне нет своих правок).
6. После полного сброса Colab повторно запустите первую ячейку: репозиторий
   будет клонирован вновь.

Файлы результатов Colab находятся в каталоге клона и тоже исчезнут при
уничтожении сеанса. Чтобы **сохранить результаты навсегда**, запустите
расчёт на компьютере и выберите нужные CSV/рисунки для отдельного коммита
в Git; либо целенаправленно выгрузите результаты из Colab в постоянное
хранилище. Исходные данные и программный код уже воспроизводимы из GitHub.

### Когда появится новый исходный файл

1. Сохраните его в `data/raw/`, например `data/raw/meter_02.csv`.
2. Проверьте схему: `Date` и `Time` либо `timestamp`/`datetime`, плюс
   `Global_active_power` в кВт. Поддерживаются `;`, запятая и табуляция.
3. Отправьте новый файл в репозиторий командами
   `git add data/raw/meter_02.csv`, `git commit -m "Add new measurements"`,
   `git push`.
4. Получите обновления в Colab через `git pull --ff-only`.
5. Запустите `python run_analysis.py --all`: новый файл будет найден
   автоматически; результаты окажутся в **отдельной** папке.

Для одного ноутбука при наличии нескольких исходников замените строку

```python
source = choose_source()
```

на

```python
source = choose_source("data/raw/meter_02.csv")
```

Это **единственная** строка выбора конкретного файла; никаких абсолютных
путей `/content` для данных больше нет.

Если структура другого файла отличается (например, `power_w` вместо
`Global_active_power` или измерения раз в 15 минут), нельзя автоматически
подставлять его в формулы для киловатт и минут. Сначала нужно явно
сопоставить столбцы, преобразовать единицы и пересмотреть шаг измерений.
Программа останавливается с понятной ошибкой, чтобы не выдавать неверные
научные результаты.

**Почему в таблицах остаются английские имена `Global_active_power` и
`Sub_metering_1`?** Это *официальные имена исходных столбцов UCI*, а не
кириллические переменные; переименовывать их без явного сопоставления
нельзя. В новых результатах используются `active_energy_kwh`,
`mean_kw`, `coverage_pct` и аналогичные понятные обозначения.

## 5. Проверки физического и статистического смысла

1. **Активная мощность** (`Global_active_power`) — кВт, а
   **электроэнергия за минуту** (`active_energy_kwh`) — кВт·ч.
   При `P = 2 кВт`: `E = 2/60 = 0,033333... кВт·ч`.
2. **Дополнительные счётчики** (`Sub_metering_1`–`3`) уже содержат
   энергию, а не мощность. Для перевода Вт·ч в кВт·ч делим на 1000.
3. **Пропуски** не подменяются нулями. Если отсутствует временная метка,
   она появляется в расчётной минутной сетке как `NaN`.
4. **Полнота периода** и **полнота календарного месяца** — разные доли.
   Для первого/последнего неполного месяца обе показаны отдельно.
5. **Средняя мощность** не равна энергии. При пропусках сумма известной
   энергии не равна истинной энергии за весь месяц.
6. **Медиана** и **среднее** описывают разные свойства распределения.
   Суточный профиль тоже не является измерением мгновенной мощности.
7. **Сглаживание** меняет максимумы и форму профиля; циклическое
   продолжение около полуночи считается модельным допущением.
8. **Анализ отсутствующих значений** имеет два варианта: случайные
   пропуски и один непрерывный участок с одинаковым числом удалений.
   Одинаковый процент пропусков не гарантирует одинаковую ошибку.

### Почему изменён график влияния пропусков

На старом рисунке три близких суточных профиля практически накладывались.
Скрытый под остальными эталонный профиль было трудно увидеть; такой график
не позволял оценить фактические отличия методов.

В новой версии верхняя панель показывает три исходных профиля с разными
цветами и стилями линий. На нижней панели показана **разность мощности с
исходным профилем** для каждого сценария: тонкая полупрозрачная линия —
неизменённые различия каждой минуты, толстая — их скользящее среднее за
15 минут только для наглядности. Численная метрика MAE вычисляется по
**исходным** данным, поэтому графическое сглаживание не подменяет результат.

Опубликованный рисунок `графики/05_влияние_пропусков.png` можно повторно
построить без чтения двух миллионов строк UCI командой
`python scripts/update_public_charts.py`: используется сохранённая таблица
`статистические результаты/05_профили_с_пропусками.csv`.

## 7. Как проверять исправления самостоятельно

В каталоге репозитория выполните:

```bash
python -m unittest discover -s tests -v
python run_analysis.py --all
```

Тесты специально проверяют:

- пропущенную временную метку на границе двух месяцев;
- отрицательную (физически недопустимую) активную мощность;
- корректное преобразование кВт в кВт·ч и Вт·ч в кВт·ч;
- чтение TXT непосредственно из ZIP репозитория;
- остановку при дублирующихся временных метках;
- ошибку при неправильной структуре исходного файла;
- создание результатов без изменения исходного файла.

Проверка на исходном UCI должна отдельно подтвердить исторические числа:
**2 075 259 строк**, **25 979 отсутствующих мощностей**, 0 пропущенных
временных меток. Эти показатели нельзя использовать как универсальные
условия для любого нового файла.

## 8. Важное ограничение

Автоматизация относится к **таблицам поминутных измерений активной мощности
по той же схеме**, что и UCI, а не к любому произвольному CSV. Для данных о
температуре, продажах или мощности в ваттах сначала требуется явно
описать смысл каждого столбца и единицы измерения. Таковы необходимые
условия научной воспроизводимости.
